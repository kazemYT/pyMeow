################################################################################################################
pyMeow C++ -- API cheatsheet (2.0.0)
https://github.com/qb-0/pyMeow

  #include <pymeow.hpp>          // everything, or include a single module header
  namespace pymeow (alias pm)    // pm::readInt(...), pm::gui::button(...), pm::sound::load(...)

  Requires C++17. Compile the sources of cpp/src/ with your project (imgui style).
  Memory / input / pixel core: no third party dependency (build with -DPYMEOW_NO_GRAPHICS).
  Overlay / render / gui / sound: raylib 5.x (+ raygui 4.0 or newer for gui.hpp).
  Linux links -lX11 -lXtst -lXinerama, Windows links gdi32 user32 psapi winmm.

  See cpp/README.md for build instructions and cpp/pymeow/pycompat.hpp for the
  snake_case names of the Python module (r_int, w_bytes, gui_button, load_sound, ...).

Exceptions (pymeow/error.hpp):
  struct Error : std::runtime_error                  // base class of every pyMeow exception
  struct NotFoundError : Error                       // process / module / window / font not found
  struct MemoryError : Error { std::uintptr_t address; int code; }   // read / write failed
  struct OutOfBoundsError : Error                    // worldToScreen: position behind the camera
  struct InvalidArgumentError : Error                // bad AOB pattern, range, font id, ...

Key codes (pymeow/keys.hpp) -- namespace pymeow::keys:
  Windows build: VK_* values (keys::End == VK_END == 0x23, keys::A == 0x41, keys::F1 ... keys::F12,
                 keys::Escape, keys::Space, keys::Left/Right/Up/Down, keys::Shift/Ctrl/Alt, ...)
  Linux build:   XK_* keysyms (keys::End == XK_End == 0xFF57, keys::Escape == XK_Escape == 0xFF1B, ...)
  The same name works on both platforms:  cfg.exitKey = pm::keys::End;

Version macros (pymeow/defs.hpp):
  PYMEOW_VERSION_MAJOR / _MINOR / _PATCH / PYMEOW_VERSION_STRING ("2.0.0")
  PYMEOW_LINUX / PYMEOW_WINDOWS, PYMEOW_ARCH_X64 / _X86 / _ARM64
  PYMEOW_API, PYMEOW_WITH_RAYLIB, PYMEOW_WITH_GUI

* Every gui control also has a (float posX, float posY, float width, float height, ...) overload,
  e.g. gui::button(0, 0, 100, 50, "text") as well as gui::button(pm::Rect{0, 0, 100, 50}, "text").
* The typed reads/writes are templates (pm::read<T>, pm::write<T>, pm::readSeq<T>, pm::writeArray<T>);
  readInt/writeInt/readFloat/... are the explicit versions of the Python r_int/w_int/r_float/... API.
* Braced lists work for the array writers: pm::writeBytes(proc, addr, {0x90, 0x90});
* pm::read<MyStruct> / pm::write<MyStruct> replace r_ctype / w_ctype (use #pragma pack(1) to match
  the layout of the game).
* Functions without a "try"/"NoExc" prefix throw a pymeow::Error subclass on failure.
* Python names: include <pymeow/pycompat.hpp> for pm::open_process, pm::r_int, pm::w_bytes,
  pm::aob_scan_module, pm::overlay_init, pm::gui_button, pm::load_sound, pm::get_color, ...
